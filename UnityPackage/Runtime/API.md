# LitheEcs API Reference

Last updated: September 3, 2026  
Target: `LitheEcs` (`netstandard2.1`)

This document describes the current public API and its important lifetime and safety rules. The
authoritative implementation is in `LitheEcs/LitheEcs.cs` and
`LitheEcs.SourceGenerator/QueryGenerator.cs`.

## 1. Overview

- LitheEcs is a managed C# archetype ECS.
- Components and relation identifiers are `struct` types.
- The library does not impose a built-in system or scheduler model.
- Record structural changes during query iteration in an `EntityCommandBuffer`.
- Unless stated otherwise, a World and its queries and collectors are intended for one thread.
- Component type IDs have no fixed upper limit. IDs 0 through 255 use an inline bit set; higher IDs
  use lazily allocated overflow storage.

```csharp
using LitheEcs;

public struct Position { public float X, Y, Z; }
public struct Velocity { public float X, Y, Z; }
```

## 2. World and entity lifecycle

### Create and dispose a World

```csharp
using var world = new World();
using var reservedWorld = new World(defaultCapacity: 10_000);
```

`defaultCapacity` is the initial entity capacity. A negative value throws
`ArgumentOutOfRangeException`. Operations after `Dispose()` generally throw
`ObjectDisposedException`.

### Spawn and despawn

```csharp
Entity entity = world.Spawn();

var entities = new Entity[1_000];
world.SpawnBatch(entities.Length, entities);

world.Despawn(entity);
world.DespawnBatch(entities);
```

If the result span passed to `SpawnBatch` is shorter than the requested count, only the entities
that fit are written. Despawning increments the entity version and invalidates old handles.
Components, bindings, and both incoming and outgoing relations are removed. Despawning an invalid
or already dead entity is a no-op.

### Identity and liveness

```csharp
bool alive = world.IsAlive(entity);
bool alsoAlive = entity.IsAlive;

EntityId id = entity.Id;
if (world.TryGetEntity(id, out Entity resolved))
{
    // resolved belongs to world
}
```

`Entity` is a readonly struct identified by its World, index, and version. `EntityId` contains only
the index and version and is local to a World. Do not compare or transfer IDs across Worlds or use
them as persistent identifiers. `default(EntityId)` is always invalid; versions begin at 1.

## 3. Components

An `Entity` exposes `Index`, `Version`, `World`, `Id`, and an `EntityData` view through `Data`.
Its string representation includes the index, version, and World identity; `default(Entity)` is
rendered as `Entity(None)`.

```csharp
entity.Add(new Position { X = 1 });
entity.Add<Disabled>();

bool has = entity.Has<Position>();
ref Position position = ref entity.Get<Position>();
bool removed = entity.Remove<Position>();

if (entity.TryGetRef<Position>(out var positionRef))
    positionRef.Value.X += 1;
```

Equivalent World APIs are available:

```csharp
world.AddComponent(entity, new Position());
world.AddComponentBatch(entities, new Position());
ref Position position = ref world.GetComponent<Position>(entity);
bool has = world.HasComponent<Position>(entity);
bool removed = world.RemoveComponent<Position>(entity);
```

Adding an existing component replaces its value. Getting a missing component is invalid.

When runtime validation is compiled in, using a `Ref<T>` after a structural change involving the
same component type throws `InvalidOperationException`. In all configurations, do not retain
component references across component additions or removals, despawns, or storage growth.

## 4. Queries

### Iteration

```csharp
foreach (ref var position in world.Query<Position>())
    position.X += 1;

foreach (var (position, velocity) in world.Query<Position, Velocity>())
    position.Value.X += velocity.Value.X;
```

`RefItem<T>.Value` returns a `ref` to the component. Callback forms also expose the matching entity:

```csharp
world.Query<Position, Velocity>().ForEach(
    (in Entity entity, ref Position position, ref Velocity velocity) =>
    {
        position.X += velocity.X;
    });
```

Use a struct action to avoid delegate dispatch on a hot path:

```csharp
public struct MoveAction : IQueryAction<Position, Velocity>
{
    public float DeltaTime;

    public void Execute(in Entity entity, ref Position position, ref Velocity velocity)
    {
        position.X += velocity.X * DeltaTime;
    }
}

var action = new MoveAction { DeltaTime = deltaTime };
world.Query<Position, Velocity>().ForEach(ref action);
```

Typed queries support one through eight components. APIs for five through eight components are
generated by the source generator.

For an entity-oriented snapshot of a query, use `EntityQuery.Result()`. The result remains valid
until a relevant structural change occurs; request a new result after invalidation.

```csharp
var entityQuery = world.Query()
    .With<Position>()
    .Without<Disabled>()
    .Any<Grounded, Flying>();

EntityQueryResult result = entityQuery.Result();
foreach (var entity in result)
    Process(entity);
```

### Filters

```csharp
var query = world.Query<Position, Velocity>()
    .With<Player>()
    .Without<Disabled>()
    .Any<Grounded, Flying>();

if (query.Matches(entity))
{
    // The current component layout matches the query.
}
```

The example means `Position AND Velocity AND Player AND NOT Disabled AND (Grounded OR Flying)`.
Repeated `Any` calls add types to the same OR-set.

### Safety rules

- Do not structurally modify a World while iterating a query. Record changes in the ECB and play
  them back after iteration.
- Mutating an existing component value through `ref` is not a structural change.
- When runtime validation is compiled in, structural changes during traversal are detected at a
  subsequent traversal boundary.
- Do not use a query after its World is disposed.

### Aligned chunks

`TryGetAlignedChunk()` exposes aligned component spans only when the query is unfiltered and its
matching data occupies at most one non-empty chunk. It returns `false` instead of throwing when
those conditions are not met.

```csharp
if (world.Query<Position, Velocity>().TryGetAlignedChunk(out var chunk))
{
    Span<Position> positions = chunk.Component1;
    Span<Velocity> velocities = chunk.Component2;
}
```

## 5. JobQuery and Unity Burst

`AsJobQuery()` restricts projected components to `unmanaged` types and exposes synchronous leases:

```csharp
using var ranges = world.Query<Position, Velocity>()
    .AsJobQuery()
    .AcquireRanges();

for (var i = 0; i < ranges.RangeCount; i++)
{
    JobQueryRange<Position, Velocity> range = ranges.GetRange(i);
    Span<Position> positions = range.Components1.Span;
}
```

Structural changes and World disposal are rejected while a lease is active. Do not retain its
`Memory<T>`, spans, or pointers after disposal. Always dispose the lease with `using` or `finally`.

The Unity package includes `LitheEcs.Unity.Jobs`. It passes one- through three-component JobQueries
to synchronous Burst jobs as pinned, zero-copy views:

```csharp
using Unity.Burst;
using LitheEcs.Unity.Jobs;

var movement = new MovementAction { DeltaTime = deltaTime };
world.Query<Position, Velocity>().AsJobQuery().RunBurst(ref movement);

[BurstCompile]
public struct MovementAction : IBurstQueryAction<Position, Velocity>
{
    public float DeltaTime;

    public void Execute(int index, ref Position position, ref Velocity velocity)
    {
        position.X += velocity.X * DeltaTime;
    }
}
```

`RunBurst()` schedules all ranges and completes their combined dependency once.
`RunBurstUnsafe()` operates through direct pointers and omits NativeContainer bounds, alias, and
dependency checks. Do not access the same columns concurrently or retain pointers or JobHandles
outside the synchronous call.

## 6. Managed parallel queries

Queries with one through eight components can run ranges on persistent World-owned workers:

```csharp
world.Query<Position, Velocity>()
    .Without<Disabled>()
    .AsParallelQuery(minimumEntityCount: 1_024, batchSize: 1_024)
    .Run((positions, velocities, entities) =>
    {
        for (var i = 0; i < positions.Length; i++)
            positions[i].X += velocities[i].X * deltaTime;
    });
```

`EntityRange` avoids copying entities. Its length and indexing match the component spans.
`entities.Offset` is a contiguous position in the current query result, not an entity index, and is
not stable between executions.

- Parallel queries cannot be nested or run concurrently on the same World.
- Structural changes during execution throw `InvalidOperationException`.
- Worker exceptions are returned in an `AggregateException`.
- The ECB is owner-thread-only. Collect requests safely and record them after `Run()` returns.
- Users must synchronize captured shared state.
- Below `minimumEntityCount`, execution is sequential. Its default is 4,096.
- Large archetypes are split into `batchSize` ranges. Its default is 4,096.

## 7. EntityCommandBuffer

Each World owns one reusable, single-owner-thread command buffer:

```csharp
var ecb = world.CommandBuffer;

DeferredEntity deferred = ecb.Spawn();
DeferredEntity initialized = ecb.Spawn(new Position(), new Velocity());
ecb.Despawn(entity);
ecb.AddComponent(entity, new Position());
ecb.AddComponent(deferred, new Position(), new Velocity());
ecb.AddComponentBatch(entities, new Position());
ecb.RemoveComponent<Position>(entity);
ecb.AddRelation<FriendsWith>(source, target);
ecb.Playback();
```

`Spawn(...)` and `AddComponent(...)` accept two through four components in one call. These
overloads validate the entity and acquire the ECB lock once, while preserving the same component
command order as individual calls.

- Commands execute in recording order.
- Recording or playback from another thread throws `InvalidOperationException`.
- Entities from another World are rejected while recording.
- Commands and payloads are cleared after playback, whether it succeeds or fails.
- Playback is not transactional; already applied commands are not rolled back.
- Spawn callbacks run during playback.

## 8. EntityTemplate

An `EntityTemplate` is a reusable component layout with default values:

```csharp
var template = world.CreateTemplate()
    .Add(new Position { X = 10 })
    .Add(new Velocity { X = 1 })
    .Add(new Health { Value = 100 });

Entity entity = template.Spawn();
template.SpawnBatch(1_000);
```

Adding the same component type replaces its template value. Singleton components cannot be
batch-added to multiple entities.

## 9. Singleton entities

Singleton marker components implement `ISingleton`:

```csharp
public struct GameSettings : ISingleton { public float Gravity; }

var globals = world.Spawn();
globals.Add(new GameSettings { Gravity = 9.81f });

Entity singleton = world.Singleton<GameSettings>();
bool exists = world.HasSingleton<GameSettings>();
bool found = world.TryGetSingleton<GameSettings>(out Entity entity);
```

Adding the same singleton type to multiple entities in one World throws
`InvalidOperationException`. The entity is singleton; regular components attached to it are not.

## 10. Managed references and bindings

`Link<T>` stores a managed reference as a component:

```csharp
entity.Add(Link.With(gameObject));
GameObject linked = entity.GetLink<GameObject>();
var query = world.Query<Position>().With<Link<GameObject>>();
```

Bindings provide reverse lookup from an external object or value. Class keys use reference
identity; struct keys use value equality:

```csharp
entity.Bind(gameObject);

if (world.TryGetEntity(gameObject, out var boundEntity))
    Use(boundEntity);

Entity required = world.GetEntity(gameObject);
entity.Unbind(gameObject);
```

The same reference or equal value cannot be bound to multiple entities in one World. Bindings are
removed on despawn. Link and Bind are separate features.

## 11. Relations

A relation type is a struct used as a type identifier:

```csharp
public struct FriendsWith { }

source.AddRelation<FriendsWith>(target);
bool exists = source.HasRelation<FriendsWith>(target);

ReadOnlySpan<Entity> targets = source.GetRelations<FriendsWith>();
ReadOnlySpan<Entity> sources = world.GetEntitiesWithTarget<FriendsWith>(target);

source.RemoveRelation<FriendsWith>(target);
```

When exactly one target exists, retrieve it with `GetRelation<T>()` or `TryGetRelation<T>()`. With
zero or multiple targets, `GetRelation<T>()` throws and `TryGetRelation<T>()` returns `false`. Use
`GetRelations<T>()` when multiple targets are possible. Source and target must be alive entities in
the same World. Despawning either removes the relation. Relations use separate storage from
components.

## 12. Reactive EntityCollector

A collector records component events since its last `Clear()`; it is not a view of current state.

```csharp
using var collector = world
    .Observe<Health>(ComponentEvent.KeyAdded | ComponentEvent.KeyChanged)
    .Or<Status>(ComponentEvent.KeyRemoved);

foreach (var entity in collector)
    if (entity.IsAlive)
        Process(entity);

collector.Clear();
```

- `Or<T>()` adds a trigger. Collectors do not have `And` or `Any` operators.
- Each entity appears once until `Clear()`.
- Replacing an existing component with `AddComponent` emits `KeyChanged`.
- Direct mutation through a query or `Get<T>()` reference does not emit `KeyChanged`.
- A removed component is already absent when its event is collected.
- An entity collected because of despawn may already be dead.
- `Clear()` preserves subscriptions; `Dispose()` unregisters subscriptions.
- Collectors store entity handles, not old or new component values.
- Disposing a World invalidates its collectors.

Combine a collector with a query for current-state filtering:

```csharp
using var collector = world.Observe<Health>(ComponentEvent.KeyChanged);
var filter = world.Query<Health, Player>().Without<Dead>();

foreach (var entity in collector)
    if (filter.Matches(entity))
        Process(entity);
```

## 13. Structural batching and diagnostics

`BeginStructuralBatch()` combines a sequence of direct structural operations into one deferred
flush boundary. Dispose the returned scope before querying or otherwise consuming the final
structure.

```csharp
using (world.BeginStructuralBatch())
{
    entity.Add<Position>();
    entity.Add<Velocity>();
    entity.Remove<Disabled>();
}
```

In diagnostics-enabled Debug builds, diagnostics APIs create snapshots so tooling can inspect a
World without retaining references to mutable internal storage. These APIs are not compiled into a
normal Release build:

```csharp
WorldDiagnosticsSnapshot worldSnapshot = world.CreateDiagnosticsSnapshot();
EntityListDiagnosticsSnapshot entities = world.CreateEntityDiagnosticsSnapshot();
EntityDiagnosticsSnapshot entitySnapshot = world.CreateEntityDiagnosticsSnapshot(entity);

world.ResetAllocationDiagnostics();
AllocationDiagnosticsSnapshot allocations = world.GetAllocationDiagnostics();
string report = world.FormatAllocationDiagnostics(allocations);
```

Snapshot creation and formatting are diagnostic operations and may allocate. Do not treat them as
hot-path APIs.

### Compile symbols

Runtime validation and diagnostics are compiled in only when `RELEASE` is not defined. They can be
removed independently by defining these symbols:

- `DISABLE_LITHEECS_VALIDATION` removes Query structural-version checks and `Ref<T>` lifetime
  checks. Entity liveness, World ownership, disposed-state, and thread-ownership checks remain.
- `DISABLE_LITHEECS_DIAGNOSTICS` removes diagnostic snapshot types and APIs, allocation counters,
  and their associated tracking code.

These symbols are useful in environments that do not define `RELEASE` but still require the
lower-overhead build. Define them for every assembly compilation that includes the LitheEcs source.

## 14. Errors and lifetime rules

- Passing an entity from another World generally throws `InvalidOperationException`.
- Instance operations on `default(Entity)` throw because it has no World.
- Operations on a disposed World throw `ObjectDisposedException`.
- Do not use queries, ECBs, collectors, or entities beyond their World's lifetime.
- Do not retain component references or relation spans across structural changes to their backing
  storage.
